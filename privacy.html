Alontito — Политика конфиденциальности

Последнее обновление: 30 августа 2026 (версия 1.1) · Автор: R_stepanov
⚠️ Это техническое описание того, что реально происходит с данными в коде приложения — написано разработчиком, не юристом. Это не заменяет юридически оформленную политику конфиденциальности и не гарантирует соответствие 152-ФЗ "О персональных данных" РФ или другим применимым законам.

Какие данные собираются

  • Номер телефона — только для входа по SMS-коду
  • Юзернейм, отображаемое имя, эмодзи-аватар — вводится пользователем добровольно
  • Текст сообщений и фотографии, отправленные в чатах
  • Время активности в приложении — для расчёта титулов
  • Записи в разделе "Данные" — только если пользователь сам их туда добавил

Архитектура хранения — два независимых сервера

identity-server — единственное место, где хранится номер телефона (зашифрован, AES-256-GCM) и пароль от раздела "Данные" (необратимо хеширован, bcrypt). Недоступен напрямую из интернета — принимает запросы только от messenger-server по секретному внутреннему ключу.
messenger-server — хранит переписку (тексты сообщений зашифрованы в базе, AES-256-GCM), фотографии и публичный профиль. Номер телефона этот сервер не хранит вообще.

Кто имеет доступ

  • Пользователи видят только свою переписку и публичные профили собеседников
  • Администратор (номер +79950023339) видит список пользователей с замаскированными номерами (например, +7999••••39), может блокировать аккаунты и удалять отдельные сообщения — но не может прочитать пароль раздела "Данные" ни при каких условиях
  • Разработчик имеет доступ к серверам как оператор инфраструктуры

Как защищены данные

  • Шифрование сообщений в базе данных (AES-256-GCM)
  • Необратимое хеширование паролей хранилища (bcrypt)
  • Лимит попыток ввода SMS-кода (5 попыток, дальше нужен новый код)
  • Раздел "Данные" — отдельный пароль + свежий SMS-код при каждом входе; ключ шифрования содержимого выводится из пароля и не сохраняется на диске
  • Ограничение частоты запросов (rate limiting) против автоматического перебора

Alontito — Privacy Policy

Last updated: August 30, 2026 (version 1.1) · Author: R_stepanov
⚠️ This is a technically honest description of what actually happens to data in the app's code — written by the developer, not a lawyer. It does not replace a legally drafted privacy policy and does not guarantee compliance with Russian Federal Law 152-FZ or any other applicable law.

What data is collected

  • Phone number — only for SMS code login
  • Username, display name, emoji avatar — entered voluntarily by the user
  • Message text and photos sent in chats
  • Time spent active in the app — used to calculate titles
  • Entries in the "Data" vault — only if the user added them

Storage architecture — two independent servers

identity-server — the only place your phone number is stored (encrypted, AES-256-GCM) and your vault password (irreversibly hashed, bcrypt). Not directly reachable from the internet — accepts requests only from messenger-server via a secret internal key.
messenger-server — stores chat messages (encrypted at rest, AES-256-GCM), photos, and public profile info. This server never stores your phone number at all.

Who has access

  • Regular users only see their own conversations and other users' public profiles
  • The administrator (+79950023339) can see a user list with masked phone numbers (e.g. +7999••••39), can ban accounts and delete individual messages — but can never read a vault password under any circumstances
  • The developer has server access as the infrastructure operator

How data is protected

  • Messages encrypted at rest (AES-256-GCM)
  • Vault passwords hashed irreversibly (bcrypt)
  • SMS code attempt limit (5 tries, then a new code is required)
  • The "Data" vault requires a separate password plus a fresh SMS code on every unlock; the content encryption key is derived from the password and never written to disk
  • Rate limiting against automated brute-force attempts
